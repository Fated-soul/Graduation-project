# 结构验证

NWB 文件在进入分析流程前应通过格式验证。验证用于检查文件是否符合 NWB 规范、必需字段是否存在以及对象关系是否有效，但通过验证不代表数据本身不存在噪声，也不代表实验设计合理。平台应分别记录“格式可读取”“结构验证通过”和“证据可用于分析”三个层次的状态。

# 时间与单位

时间序列需要明确单位、采样时间和时间参考。规则采样可以使用起始时间与采样率，非规则采样应保存显式时间戳。信号值的单位和换算关系也必须保留；如果单位缺失或含义不明确，只能展示原始数值，不能擅自换算为常用生理单位。

# 对象与元数据

会话开始时间、实验动物标识、实验描述、设备和采集对象是后续溯源的重要元数据。载入数据时应保存原文件路径、DANDI 资产标识、固定版本和处理状态，使数据库中的会话能够追溯到具体 NWB 文件。派生统计不应覆盖原始元数据。

# 完整性检查

结构验证之后还应检查时间戳是否单调、样本数是否与时间轴一致、区间起止是否合法、采样率是否合理，以及模态覆盖范围是否与会话描述一致。发现局部缺失时应记录缺失范围，而不是自动扩展相邻值填满整个会话。

# Agent 使用边界

Agent 引用 NWB 证据时应同时考虑验证状态、单位、时间覆盖和处理来源。仅有“文件可打开”不能证明其中所有模态都适合当前问题；关键元数据缺失时，应降低证据充分程度并指出需要补查的项目。
